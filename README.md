# 呼噜呼噜

一只会主动让路的蓝色单眼桌面宠物。忙的时候陪你工作，闲的时候摸摸头、聊一句，或者吃一屏豆豆。

![蓝色单眼宠物](assets/blue-one-eye-mascot.svg)

显示名称为「呼噜呼噜」；npm 包名 `blue-one-eye-pet`、命令 `bluepet` 与应用标识保持兼容。

当前版本 **0.4.5** · **macOS** · **MIT（代码）** · Electron + 原生 JavaScript

## 安装与启动

### macOS 应用

当前不提供 GitHub Release 附件；公开仓库继续保留源码。需要安装包时请从可信源码本地打包，并核对构建环境与校验值。

1. Apple Silicon（M 系列）选择 `mac-arm64` 包；Intel 需要单独构建的 `mac-x64` 包，不能混用。
2. 打开 DMG，将 **呼噜呼噜.app** 拖入「应用程序」；也可解压 ZIP 后移动进去。
3. 启动后看屏幕顶部菜单栏的单眼宠物细轮廓图标，Dock 不显示图标。
4. 可在菜单中开启「登录时自动启动」。退出请使用「退出呼噜呼噜」，隐藏不会退出后台。

应用包自带 Electron，不需要安装 Node.js。当前本地 release 包没有 Developer ID 签名、未经 Apple 公证，macOS 可能阻止首次打开；只运行你确认来源和校验值可信的包，不要关闭系统安全保护。

### 命令行安装

需要 **Node.js 22.12+**、npm，以及首次安装时下载 Electron 的网络连接。下载 `.tgz` 后，在其所在目录执行：

```bash
npm install -g ./blue-one-eye-pet-0.4.5.tgz
bluepet
```

不依赖 npm registry 已发布同名包。npm 7+ 会安装 Electron peer 依赖；`.tgz` 本身不包含 Electron 二进制。

```bash
bluepet --mode=dodge     # 自由让路，默认模式
bluepet --mode=pet       # 陪伴、互动与移动
bluepet --mode=beans     # 吃豆豆小游戏
bluepet --foreground    # 前台运行，方便查看错误
```

默认启动后脱离终端、常驻后台；已运行时，命令把模式切换交给同一实例。旧参数 `--mode=control` 兼容映射为 Pet。CLI / 源码运行时，「登录时自动启动」不可用，请用打包后的 `.app`。

### 从源码安装

```bash
git clone https://github.com/ken0122/huluhulu.git
cd huluhulu
npm ci
npm link
bluepet
```

`npm link` 让命令行入口指向当前源码目录；不要移动或删除目录。卸载命令行入口使用 `npm uninstall -g blue-one-eye-pet`，再从菜单退出正在运行的实例。

## 三种模式

| 模式 | 行为 | 操作 |
| --- | --- | --- |
| Dodge · 自由让路 | 自主散步、点击穿透；光标慢慢靠近就让路，快速逼近会弹开再减速，不自动消失 | 正常使用桌面即可 |
| Pet · 互动与移动 | 留在身边，不自主散步；光标靠近会让路、快速逼近会闪开，进入角色区域后停下供互动；停止躲闪超过 3 秒会平滑回到拖拽或方向键确定的稳定位置，连续躲闪不会漂移；安静 8–15 秒后偶尔张望、伸展、轻弹或摇摆，并用漫画气泡冒出短语气词 | 鼠标互动；选 Pet 或点击后用方向键移动，松键停止；Esc 释放键盘焦点 |
| 吃豆豆 · 吃颗豆豆 | 当前屏幕出现遮罩和随机豆豆，每清完一屏，速度再乘 **1.3** | 方向键移动，Esc 退出并回到 Pet |

Pet / Dodge 互相切换保留物理惯性：平滑起步，回到上次 Pet 停留位置时减速停稳；拖拽、方向键、聊天和隐藏可中断过渡。桌面原生窗口移动跟随屏幕渲染帧，按经过时间计算速度。

所有内置、已添加和以后导入的角色共享两项标准动作：支持眼神的角色会在 Dodge、吃豆豆 和角色预览中看向光标；Pet 中光标静止超过 5 秒后瞳孔回中放松，光标再次移动 1px 即恢复注视。发生明确的水平移动时，形象会朝移动方向左右翻转，停下或仅上下移动时保留最后朝向。导入角色会在本地从已确认的眼睛框中定位眼白、原有固定瞳孔和眼白颜色，用同色遮片替换为可移动瞳孔，并按真实眼白余量分别计算横向与纵向视线范围，不改写原图；无法可靠定位时才使用受限的眼框或头部回退位置。

吃豆豆 初始速度 280 px/s，之后为 364、473.2……，不是每屏固定加 30% 初始速度；重新开局重置。顶部 96px 留给分数、倍率与操作提示，宠物和豆豆不会进入该区域。反弹和穿屏保留本帧剩余路程；游戏窗口缩小时，剩余豆豆会按新的可玩区域重排，不重置分数、关卡和方向。游戏角色没有眼皮。

### Pet 怎么玩

| 操作 | 小反应 |
| --- | --- |
| 按住并拖动 | 移动超过 6px 开始拖拽，松开停在新位置 |
| 不按鼠标，在头顶来回摸 | 短暂眯眼，“摸摸头，好舒服” |
| 不按鼠标，在肚子左右挠 | 扭动怕痒，“哎呀呀，好痒！” |
| 点击肚子 | 软软缩一下，“哎呀！戳到肚肚啦” |
| 点击脸颊 / 停留陪伴 | 贴贴、蹭蹭 |
| 按住约 0.65 秒，不拖动 | 抱抱 |
| 点击耳朵 / 眼睛附近 | 害羞 / 开心跳一下 |

互动气泡按实际文字排版测量原生窗口高度，标点、中英文混排和已有长台词均向上扩展，避免按字数估算造成裁切。反应有冷却，不播放声音。拖拽不会同时触发点击或抱抱；Esc、失焦、切换模式会结束拖拽。切到其他应用后不接收方向键，聊天输入时也不会误移动。

保持原 SVG 的轮廓、配色和结构，不加腿或身体图层；没有明确足状特征的角色，会让底部轮廓左右交替起伏来模拟双足：矢量角色形变安全身体路径，PNG 包装角色使用只作用于已确认 body 下段的运行时位移。已有腿部时保留整体起伏。桌面角色 84px、游戏 64px。桌面眼睛大多数时间睁开，每隔约 3.8–7.2 秒短促眨眼；系统「减少动态效果」会关闭弹射、眨眼及自主小动作，保留普通避让。

## 快捷键与菜单

`⌃` 是 Control，`⌥` 是 Option，`⌘` 是 Command。

状态栏菜单依次提供「角色…」「外观」「语言」「快捷键」，位于同一分区；所有带按键的操作都收在「快捷键」二级菜单。外观可跟随 macOS，也可固定为浅色或深色；聊天气泡、互动提示、聊天设置和角色库会实时同步，吃豆豆 保留固定深色夜幕。语言首次跟随系统首选语言，可手动选择简体中文、繁体中文、英语、日语、法语、德语或俄语；不支持的系统语言回退英语。切换无需重启，也不会重载窗口、清空聊天输入、角色编辑草稿或游戏进度。

中文界面显示「呼噜呼噜」，其他语言显示 **Hulu Hulu**；安装包、npm 包名和 CLI 不变。界面、菜单和内置角色资料使用当前界面语言。自定义角色的名称、人格、互动台词和彩蛋按语言分别保存：优先显示当前语言已有版本，没有时沿用最近编辑或生成的已有文字，再回退原文，不替换成通用安全短句。切换语言本身不会请求模型或自动创建译文。

| 操作 | 默认快捷键 |
| --- | --- |
| 粒子消散隐藏 / 召唤到当前屏幕初始位置 | **⌃⌥B** |
| 呼出头顶聊天气泡 | **⌃⌥Space** |
| Dodge → Pet → 吃豆豆 → Dodge 循环切换 | **⌃⌥⌘M** |
| 切换到下一个宠物 | **⌃⌥⌘C** |

模式和宠物循环键有 400ms 防连发；模式循环在手动隐藏时不响应，宠物循环只更换形象而不会唤醒宠物。单纯打开菜单不会显示宠物；「召唤宠物」与隐藏 / 显示共用 **⌃⌥B**，从隐藏状态恢复时会把宠物放回当前屏幕右下角的初始位置。隐藏后不会自行现身。

状态栏菜单的 `Pet · 互动与移动 ⓘ` 提供操作说明；在 macOS 上悬停该菜单项即可查看拖动、长按、摸头挠肚肚和方向键提示。宠物本体不再使用会遮挡角色的浏览器原生 tooltip。

默认组合避开常见系统快捷键，但无法保证不与第三方软件自定义快捷键冲突。注册失败会通知，仍可从菜单操作。要改快捷键，先退出当前实例，再从终端启动：

```bash
BLUEPET_HIDE_SHORTCUT="Control+Alt+H" \
BLUEPET_CHAT_SHORTCUT="Control+Alt+P" \
BLUEPET_MODE_SHORTCUT="Control+Alt+Command+N" \
BLUEPET_CHARACTER_SHORTCUT="Control+Alt+Command+J" \
bluepet
```

这些环境变量作用于本次启动；给已运行实例再次传入环境变量不会重新注册快捷键。

隐藏时先蓄力鼓起、裂开，再散成高对比蓝白碎片与两层扩散光环，动画约 420ms；主进程以 460ms 兜底隐藏窗口。开始隐藏即释放鼠标交互，期间再次恢复或选模式会取消消散；系统开启「减少动态效果」时直接隐藏。Pet、Dodge、聊天和吃豆豆均支持。

## 聊天与隐私

从 Dodge 打开聊天时停止自主散步，仍响应光标靠近与快速逼近的闪避；光标进入气泡时停稳，方便输入。气泡外的透明区域与角色继续点击穿透，Pet 聊天保持静止。气泡为 248×140px，采用无尾尖的柔软圆角、单眼状态标记和圆形发送按钮，输入区不叠加装饰层。聊天输入支持 macOS 的 ⌘A、⌘C、⌘V、⌘X、⌘Z 和 ⇧⌘Z 编辑快捷键。

聊天使用用户配置的 **Anthropic Messages 兼容 HTTPS 接口**。从状态栏打开「聊天设置…」，填写 Base URL、API Key、对话模型和可选的图片分析模型；Base URL 可以填写域名、以 `/v1` 结尾的地址或完整 `/v1/messages` 地址；应用会保留网关前缀，补全为单个 `/v1/messages`，避免双斜线或重复版本路径。保存后下次请求立即生效，但不会发起连接测试。

切换角色后，聊天系统提示词由主进程根据当前角色已校验的人格资料生成；renderer 不能自行指定人格。导入新角色时使用图片分析模型生成质量、气质、互动语言、彩蛋和部件框草稿；图片分析模型留空时复用对话模型，接口与模型必须实际支持 Anthropic 图片输入。

为兼容常见网关，请求同时发送 `x-api-key` 与同值的 `Authorization: Bearer`，只发往用户明确填写的同一个 HTTPS 地址，并拒绝重定向。请只配置你信任的服务；应用不验证第三方服务的安全、隐私、计费或模型能力。

密钥通过 Electron `safeStorage` 使用 macOS 系统加密，密文保存在应用 userData 的 `api-settings.enc` 文件中；系统加密不可用时拒绝保存，不降级为明文。已保存密钥不会回填页面；留空保留、输入新值替换。「清除本机配置」会删除此文件。旧版仅含特定服务地址和密钥、但没有模型字段的配置无法自动迁移，需要清除后重新填写。

配置优先级为：聊天设置中保存的本机配置 → 同一进程中的 `BLUEPET_API_BASE_URL`、`BLUEPET_API_KEY`、`BLUEPET_CHAT_MODEL` 和可选 `BLUEPET_VISION_MODEL`。不再读取 CC Switch、Claude Code settings 或其他 provider 的配置；未配置时直接提示用户设置。普通陪伴和游戏不需要 API。

聊天会把你输入的文字和固定宠物系统提示词发送到所配置 API；每次请求不附带历史消息，也不将对话写入文件。当前气泡的回复会留在内存中，关闭再打开仍可能看到上次回复；关闭气泡不会取消已发送的请求。凭据只在主进程内使用，不回传 renderer、不进入日志或安装包；设置窗口仅临时接收新密钥，保存成功后清空。输入最多 500 个 UTF-16 代码单元，回复最多 50 个可见字符；HTTP 请求 15 秒超时。

## 一张小纸条

仍从聊天气泡输入，例如“10分钟后提醒我喝水”或“明天下午3点提醒我带充电器”。用户配置的对话模型负责识别意图；时间或事项不明确时先问清楚。接口和模型需要能按提示返回紧凑 JSON，解析失败会明确提示未记成功，不会把普通聊天回复当作已建立提醒。

同一时间只记一条、只支持一次性提醒。已有纸条时，新提醒会展示新旧事项供选择，不直接覆盖；可点“已记一条”查看和取消，也可从聊天询问或取消。到点气泡轻弹并闪过三颗星星，随后静态停留；“收到啦”清除纸条，关闭或继续聊天只收起，不重复弹出。没有稍后按钮。

提醒不抢键盘焦点，正在聊天时只显示到期标记，不覆盖输入。手动隐藏或吃豆豆中到期时使用一次无事项正文的系统通知，恢复后仍可查看；系统通知受 macOS 权限及专注模式影响。减少动态效果开启时只有静态样式。

纸条单独加密保存在本机 userData 的 `reminder-v1.enc`，与聊天历史分开；查看、确认和按钮取消不联网。每次聊天请求时，当前纸条与澄清草稿的必要信息、提交时间及本地时区会随当前输入发送到所配置 API，用于识别查看、取消或补充等意图，不发送聊天历史。应用退出、电脑关机或睡眠时无法准时提醒，启动或唤醒后补提醒。加密或保存失败时不会承诺记住，不适合关键事务提醒。具体实现约定见源码的 `docs/reminders.md`。

## 常见问题

- **没看到 Dock 图标？** 这是菜单栏常驻应用，Dock 图标默认隐藏。菜单栏图标是无底板的模板轮廓，由 macOS 随菜单栏明暗自动着色，与系统图标保持一致。
- **找不到宠物？** 先按 `⌃⌥B`，或从菜单选择「找回宠物到当前屏幕」。换显示器、休眠恢复有自动恢复处理；桌面宠物与游戏窗口均有意外隐藏 watchdog，恢复不抢焦点，手动隐藏除外。
- **Pet 方向键没反应？** 先切到 Pet 或点击它获取焦点；Esc 和切到别的应用会释放控制。
- **聊天连不上？** 检查 Base URL、API Key、模型标识及接口是否兼容 Anthropic Messages。不要把密钥粘贴到 issue 或日志中。
- **`bluepet: command not found`？** 执行 `npm prefix -g`，确认其 `bin` 目录在 PATH；源码安装确认执行过 `npm link`。
- **升级后仍是旧行为？** 从菜单退出旧实例，安装新包再启动；后台实例不会在文件更新后自动重载。不要同时运行源码版和应用版。

### 已知限制

- **游戏中途修改「减少动态效果」时，豆豆呼吸不会立即更新。** 该设置在游戏加载时读取，重开游戏后生效；宠物形变和眼睛动画另有动态监听。
- **聊天错误统一显示。** 当前气泡不区分凭证错误、限流、超时和网络失败，不应仅凭提示断定是哪一种原因。

## 开发与验证

贡献前阅读 [AGENTS.md](AGENTS.md)，当前视觉与交互约束见源码仓库内的 `DESIGN.md`（不随安装包分发）；`PRODUCT.md` 是早期构想，不是当前功能清单。目前实际验证平台为 macOS；没有 Windows / Linux 安装、开机启动或交互验收承诺。

```bash
npm ci
npm start               # 前台开发运行
npm test                # Node 单测，无真实模型请求
npm run test:desktop:smoke # 高频桌面冒烟，仍会短暂显示和聚焦窗口
npm run test:desktop    # 完整真实 Electron 窗口回归，等同于 test:desktop:release
npm run pack            # 本机架构 .app，输出 dist/
```

桌面测试需要 macOS 图形会话，并会操作窗口与焦点；先从菜单退出运行中的宠物，测试后自行重启。日常迭代先跑 `npm test`，相关功能完成后跑 smoke 或影响范围内的桌面用例，完整 release 套件留到提交收口或发布前执行。固定分层命令如下：

| 命令 | 范围 | 适用时机 |
| --- | --- | --- |
| `npm run test:desktop:smoke` | 启动、外观设置、三模式基础往返、键盘与 吃豆豆 主链路 | 每轮功能完成后 |
| `npm run test:desktop:focus` | 会主动聚焦窗口或依赖原生输入的用例 | 可接受桌面被集中打断时 |
| `npm run test:desktop:soak` | 5–10 秒眨眼、自治动作、避让返回和持续可见性观测 | 空闲时 |
| `npm run test:desktop:release` | 全部真实桌面检查 | 提交收口或发布前 |

需要按影响范围进一步缩小时，可用逗号分隔的 `BLUEPET_TEST_TAGS`，例如 `BLUEPET_TEST_TAGS='character,settings' npm run test:desktop`；也可继续用 `BLUEPET_TEST_MATCH` 按名称正则筛选。分层、功能标签和名称筛选同时设置时取交集，不会扩大测试范围。只有显式设置 `BLUEPET_TEST_CHAT=1` 才会发送一条真实模型问候。

截图写入被 Git 忽略的 `work/`。`desktop-test-results.json` 在本轮启动时重置，并记录分层、标签、筛选条件、每项耗时、总耗时、已通过用例及 `running` / `passed` / `failed` 状态；失败时记录当前失败项，之后的用例未执行。隐藏耗时独立观测原生窗口可见性，不计入截图与写盘等待。焦点被其他应用抢走可能影响键盘、长按和拖拽测试；筛选通过不能替代完整 release 回归成功。

主进程负责窗口、输入与 HTTP；`src/app-state.js` 集中定义模式、聊天、隐藏与控制状态转换，原生副作用由主进程统一同步 Pet / 吃豆豆 窗口。拖拽、聊天、隐藏和恢复共用中断清理路径；renderer 使用最小 IPC。所有窗口保持 `contextIsolation`、`sandbox`，关闭 `nodeIntegration`。逻辑回归在 `test/`，真实窗口检查在 `scripts/desktop-test.mjs`。

角色桌面回归在 HTTP 传输层注入虚构响应，实际执行图片光栅化、生成函数、IPC、采用与保存；不读取真实聊天配置。`BLUEPET_TEST_MATCH='Character import:|Character AI:' npm run test:desktop` 覆盖导入、12 个生成范围、显式翻译、语言版本保存与回退、未完成编辑、坐标精度、就地确认和报错、最小窗口及真实请求超时。

打包后可将 `BLUEPET_TEST_APP_ROOT` 设为 `.app/Contents/Resources/app.asar` 的绝对路径，复用桌面测试加载产物中的主进程、preload、renderer 与 Worker（测试驱动及图片 fixture 仍来自源码开发依赖）。可配合 `BLUEPET_TEST_MATCH='Character library|Character import'` 检查打包后的导入链路；这不是签名、公证或完整产物回归。

### 本地角色库（源码开发版）

从状态栏菜单打开「角色…」，选择呼噜呼噜、黑猫、小太阳或自己添加的角色。点击列表只预览，点击「使用角色」才切换。添加图片会创建一个新角色，不会覆盖正在使用的黑猫或其他角色；自己添加的角色可编辑名称、气质、互动台词、彩蛋和部件，也可删除，内置角色不能编辑、自动生成或删除。桌面、Dodge 和 吃豆豆 共用选择；切换不会清空聊天输入、重开游戏或唤醒手动隐藏的宠物。角色窗口是普通 macOS 窗口，不会长期置顶遮挡其他应用。

导入流程：

1. 点击「添加角色…」后，先确认你拥有使用图片并将其发送分析所需的著作权、商标、肖像、隐私及其他权利；免责声明不能代替权利人授权。
2. 在系统文件选择器中选图。图片会发送给你配置的 API；本地 Worker 同时规范化图片，模型给出质量、气质、互动语言、专属彩蛋和部件框草稿。`reject` 会阻止保存，`warn` 允许用户核对后继续。
3. 查看原图、结果及 84px / 64px 实际尺寸，修正名称、气质、每项互动短句、彩蛋和部件框；再预览步态、轻跳与彩蛋。
4. 点击「添加并使用」；「放弃添加」不保存草稿，未保存时换图、关闭窗口或按 Esc 会先请求确认。

编辑自己添加的角色时，可以补充一句不超过 300 个字符的要求，再生成全部文字、基本资料、七组互动台词、单组台词或彩蛋。生成只处理当前界面语言；需要其他语言时，先切换界面语言，再选择重新生成或 `Translate`。全部文字区块的 `Translate` 始终保留，生成和采用建议不会让按钮消失；当前语言是角色原始语言时按钮禁用。再次翻译已有目标语言版本时仍从原始语言版本翻译，不会把目标语言内容翻译成自身。各语言版本独立保留，修改一种语言不会清除其他语言。结果和「采用建议」「放弃建议」出现在发起操作的字段旁；采用后进入草稿，仍需「保存修改」才落盘。重新识别部件是单独操作，只依据真实图片。缺少兼容接口时，同一位置提供打开聊天设置的入口。

编辑表单保留角色的原始语言，切换界面语言或仅改名称不会覆盖译文。手工改动某组原文后，仅使该组旧译文失效，其他组保留；缺少译文的互动按当前语言回退。部件坐标按原始精度保存，未改动的置信度保持不变。生成使用本机已保存资料与有效草稿字段作为上下文，目标字段留空或其他分区未填完时仍可生成；采用建议不填平其他分区的未完成内容，最终保存仍须完整校验。彩蛋建议会展示名称、说明、触发互动及短句的对照；彩蛋在角色原始语言下使用已确认的独有短句，其他语言使用安全回退。

互动文案使用有效草稿中的角色气质和对话模型，采用纯文字请求。单组生成只带必要气质与当前组，固定返回 4 句不同台词，以“｜”分隔（兼容 JSON；2048 token 额度）；七组互动每组同样固定 4 句；基本资料和彩蛋也正常各用一次请求。生成不再附带任何其他语言翻译。「生成全部文字」只生成当前语言的文字，不分析图片。主动翻译只发送所选字段及一种目标语言，保留原意、台词数量及触发规则。单组包含多句时，翻译用 JSON 保留各句。生成或翻译失败不覆盖已有草稿或已保存版本。

接口标记 `max_tokens` 时，完整 JSON 仍须先解析并严格校验，合规则保留；不完整 JSON、被截断的纯文本和思考内容不会被当成成功台词。

自动生成互动台词（单组、整区、全部文字及图片导入分析）每组必须恰好 4 句；返回数量不符时最多修正一次，仍不符则拒绝采用，不复制台词凑数。手动填写与保存保持每组 1–4 句；主动翻译保留现有句数。

模型获得一次按当前区块规则缩写超长文字的机会；若修正文本仍只是超长，应用按该字段上限从末尾安全收束且不拆开 emoji 等字素。缺失、换行、格式、枚举或台词数量错误仍拒绝采用，不通过本地兜底补造内容。

翻译使用 DeepSeek 官方 `https://api.deepseek.com/anthropic/v1/messages` 时，显式发送其支持的标准 Messages 开关 `thinking: { type: "disabled" }`，首轮和修正均直接请求译文，避免 V4 默认思考消耗全部输出额度。其他接口不推测该能力，也不因模型名称自动添加参数；不添加 effort 等厂商扩展，不修改用户配置。

新图片分析和自动生成的互动台词每句最多 24 个 UTF-16 代码单元（含空格、标点）；主动翻译保留原句数和逐句原意，每句最多 50，已有和手动输入同样兼容 50。彩蛋说明生成最多 80，翻译版本最多 120；名称、触发规则和短句仍保持原有紧凑边界。“生成全部文字”需要一次返回基本资料、七组台词和彩蛋，首轮及普通修正请求含正文读取限时 90 秒；单个分区、单组台词、翻译、图片分析及其普通修正仍限时 30 秒。只有思考且耗尽额度后的唯一一次重试至少等待 90 秒。首个请求和修正请求分别计时（包含正文读取），结果或错误旁简写为“生成用时 X 秒”（翻译时为“翻译用时”）；需要调整时补充“正在调整内容…”或“调整用时 Y 秒”，无需调整时不额外提示。延长等待的重试会明确提示最多等待 90 秒，失败时显示实际使用的超时时限。诊断只在当前窗口内保留，不写入角色数据或日志。提示词按范围仅携带必要资料和约束，整区台词不携带全部旧台词，部件识别不发送角色文字。空正文、JSON 不完整、截断或不合规文字最多追加一次修正请求，额度加倍并使用该操作的独立时限；只有思考且耗尽额度时至少提高到 8192 token，并独立等待最多 90 秒；因此需要修正时可能等待更久。HTTP 错误、拒绝和超时不自动重试。文字修正只使用当前区块的生成或翻译规则，且只能补充缺失或无效字段，不能改变图片质量决定、问题枚举和部件框。完整 JSON 即使标记达到额度仍须通过校验；截断纯文本或思考内容不作为台词。状态和错误在操作位置显示，不显示服务端正文。请求只采用 Messages 兼容参数，不发送 provider 专属 thinking 或 effort 字段。

用户入口支持**彩色或单色静态 PNG/JPG**，不超过 10 MB、总像素不超过 1,048,576。硬性素材要求是：只有一个完整角色、不能裁切；透明或一致的纯色背景；正面或轻微侧面；轮廓和部件清楚。照片、复杂/渐变背景、遮挡、多角色、动画 PNG、多图 JPG 和直接 SVG 导入不受支持。透明图直接规范化；不透明图只移除与四角一致且连通的简单背景，前景比例或边缘裁切异常会被拒绝。Worker 在沙箱内生成受限的 64×64 SVG 包装，不读取 renderer 指定的任意路径。

模型结论只是可编辑建议，不等同于像素级分割或骨骼识别。部件框会调整摸头、挠痒等命中区域、部分动作原点和无腿角色的下轮廓位移范围；彩色平面形象仍以整图呈现，不会凭空生成可独立摆动的尾巴、四肢或眼皮。所有人格、短句、动作名、时长、彩蛋触发和部件坐标都经过白名单与长度/范围校验，不接受脚本、CSS 或任意选择器。自动生成只能读取主进程按角色 ID 取得的已保存受限 SVG，renderer 不能指定文件路径、模型或任意图片内容。

最多保存 20 个本地角色。新增、编辑、选择和删除都会原子写入 userData 的 `characters-v2.json`；其中只保存名称、受限 SVG、已确认的分析资料和当前选择。旧 `characters-v1.json` 可只读兼容，并在下次修改时写入 v2，旧文件不自动覆盖。原路径、生成补充要求、聊天与密钥都不进入角色数据；规范化后的图像内容会进入受限 SVG。导入时，原图只在用户明确确认权利并选择后发送给所配置 API；之后只有主动识别部件时，应用才把已保存的受限 SVG 临时渲染为 PNG，发送给配置 API 的图片模型；文案、翻译和文字修正只发送必要文字给对话模型。图片请求若因空正文、JSON 不完整或输出截断重试，会向同一接口再发送同一图片，最多一次；文字修正不重发图片。应用本身不提供公开角色分享。

### SVG 角色架构

角色按「受限素材 → 已校验分析 → 人格/互动配方 → 部件绑定 → 动作控制」分层：`character-analysis.js` 约束多模态结果，`character-profile.js` 生成纯数据互动协议，`characters.js` 组合可信定义；renderer 的 `character.js` 负责绑定和替换，`pet-interactions.js` 负责按角色隔离的语言轮换、冷却和声明式彩蛋，`character-motion.js` 统一处理动作、暂停、减少动态效果与销毁。`mascot.js` 为 Pet/吃豆豆 提供稳定控制接口，切换时替换内部 SVG、销毁旧动作并恢复当前动作状态；隐藏粒子另行刷新取样缓存。原角色源 SVG、尺寸与三种模式不变；原生窗口移动不由角色动画接管。

`character-library.js` 负责独立窗口、专用 preload、主 frame 来源校验、文件选择和主进程分析入口；`character-import.js` 负责文件头/体积/像素边界及受限 SVG 校验；`character-store.js` 负责有上限的 v2 数据、v1 兼容、串行写入与原子替换。Worker 只执行图片解码、背景规范化和受限 PNG 包装。没有引入运行时原生图片依赖，开发 CLI 使用的 sharp 仍为 devDependency。

基础 SVG 绑定不要求素材自带可操作的眼睛或特定身体路径，可使用整体移动起伏和通用互动动作；应用会为导入角色生成受限的运行时瞳孔层。黑猫和小太阳均按“网络参考素材、第三方权利未核实”的政策保留，具体风险披露见各自 NOTICE；随软件提供不代表授予使用者再次使用这些形象的权利。默认蓝色角色来自项目负责人所在公司的另一产品 IP，计划在取得限定于不相关、非竞争领域的内部授权后使用，见 `assets/blue-one-eye-mascot.NOTICE.md`。

开发者可运行以下命令（需要源码开发依赖）：

```bash
npm run character:convert -- input.png work/my-character-v1
npm run character:preview
npm run character:preview -- --verify
npm run character:preview -- --verify --keep-open
```

转换仅支持**白底或透明底的深色单色 PNG/JPG**，文件不超过 10 MB、总像素不超过 1,048,576；不适合照片、渐变或复杂背景。它将图片二值化，移除外部浅色区域及阴影，并保留封闭的不透明白色细节；边缘是有限精度的近似。输出目录必须尚不存在，父目录需已存在，生成 `character.svg` 与带校验值的 `conversion.json`，不覆盖原图或旧结果。转换全程本地、不请求模型、不自动安装角色。

预览命令加载完成后将独立窗口置前并保持打开，演示**固定黑猫样本**及 84px / 64px 效果，不切换当前桌面宠物，不加载聊天配置。关闭窗口退出预览。`--verify` 检查真实 SVG 动作、暂停/恢复、减少动态效果与原路径不变，保存 `work/black-cat-preview.png` 后自动退出；加 `--keep-open` 则验证后保留窗口供手动体验。PNG 文件只是静态截图，不是可点击的动作预览。这些检查不替代完整桌面回归。

绑定对象是应用代码内的可信数据，不是公开角色包格式。导入校验仅接受当前单色转换器的有限路径语法，或用户入口生成的固定属性、单张内嵌 PNG 包装；它不是允许任意 SVG 的通用清洗器。不得将用户上传的任意 SVG、部件选择器或脚本传给绑定层。

## Release 打包

在 macOS 源码目录执行：

```bash
npm ci
npm run release:mac
```

命令先检查 `package.json` 与 `package-lock.json` 的版本一致性、差异格式并运行单测，再生成**当前 Node 运行架构**的产物；README 版本号仍需人工同步核对。Apple Silicon 请使用 arm64 Node；Intel 使用 x64 Node。已有本机交付验证范围为 arm64，具体以对应产物的 `RELEASE.md` 和验收记录为准。

每次创建独立的 `outputs/releases/v0.4.5-mac-<arch>-<随机后缀>/`，不覆盖旧包：

| 文件 | 用途 |
| --- | --- |
| `呼噜呼噜-0.4.5-mac-<arch>-unsigned.dmg` | 拖入 Applications 安装 |
| `呼噜呼噜-0.4.5-mac-<arch>-unsigned.zip` | 解压即得应用 |
| `blue-one-eye-pet-0.4.5.tgz` | npm 命令行安装 |
| `SHA256SUMS` | 三个安装包的 SHA-256 校验值 |
| `RELEASE.md` | 基础提交、未提交状态、构建范围与安装说明 |
| `README.md` / `AGENTS.md` / `LICENSE` / `ASSETS-LICENSE.md` | 使用手册、协作指南、MIT 协议与素材权利边界 |

在产物目录校验：

```bash
shasum -a 256 -c SHA256SUMS
```

脚本同时检查 DMG / ZIP 完整性和 npm 包文件清单。打包不会运行桌面交互测试、请求聊天、签署 Developer ID、进行 Apple 公证、创建 Git tag，或上传 GitHub / npm。`RELEASE.md` 会明确标记未提交工作区，公开发布前应完成代码提交、桌面验收和签名策略确认。

只需要原始 DMG / ZIP 构建可用 `npm run dist:mac`，输出 `dist/`；完整交付用 `release:mac`。`dist/`、`work/`、`outputs/` 和安装包都不入 Git。
